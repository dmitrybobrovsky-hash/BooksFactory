## Что тестируется

**Гипотеза:** новая фильтрация входа в `bf-compiler.md` §«Фильтрация входа» позволяет compiler собрать Session для Главы 1 KS (MATERIAL 76 КБ) без обрыва. Целевой размер Session ≤ 150 КБ (мягкий лимит из `handoff_contracts.md` §«Правило размера Session-файла»).

## Задание

Запусти **только bf-compiler** на Главе 1 KS. Не запускай writer-loop. Не передавай результат в editor. Цель — проверить сборку.

**Вход:**

- `_testing/Test3_05.05.2026/session_template_KS.md`

**Применить фильтрацию по канону:**
- arenen_pool → только три арены, назначенные на Главу 1 (из continuity-блока MATERIAL_Glava_01).
- verbot_liste → §I–§VIII полностью + §IX.1, §IX.2, §IX.3 (предыдущие главы со scope: global или релевантным контекстом). Если scope не помечен — взять все §IX до текущей главы (резервный режим).

**Выход:**

## Триггеры остановки

- Если compiler обрывается (как в INCIDENT-07) — отчитайся, не пытайся повторно. Это означает, что фильтрация (вариант а) недостаточна, нужен переход к варианту (б) split-compile.
- Если итоговый Session > 200 КБ (жёсткий лимит) — отчитайся, не сохраняй файл.
- Если фильтрация технически невозможна по какой-то причине (например, нет beat_plan для Главы 1 — старый в архиве) — отчитайся.
