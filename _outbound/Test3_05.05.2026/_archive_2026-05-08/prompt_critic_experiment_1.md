# Эксперимент: bf-critic sonnet vs opus

**Цель:** эмпирически проверить, ловит ли opus-critic тонкие дефекты, которые пропускает sonnet-critic. Решение по результатам определит модель critic для всей KS.

**Гипотеза:** для книг с высокой плотностью голоса (KS) sonnet-critic пропускает тонкие повторы и сигнатурные паттерны второго порядка, замеченные при ручном анализе Главы 0:
- Структурный паттерн «Не X. Y.» (5+ вхождений на главу, не отслеживается).
- Сквозные формулы (например «снижает порог называния») между главами.
- Пропущенная атрибуция эмпирических утверждений.

## План эксперимента

### Шаг 1. Подготовка

1. Прочитать `_SESSION_STATE.md` (запись 21 — эта).
2. Сохранить копию `.claude/agents/bf-critic.md` как `.claude/agents/bf-critic.md.backup-2026-05-08`.

### Шаг 2. Прогон A (sonnet — текущий)

Если Глава 1 ещё не написана writer-loop'ом — запустить как обычно: `bf-planner → bf-compiler → coordinator (writer ↔ critic)` с критиком sonnet. Сохранить:

- Финальный draft → `Glava_01_KS_draft_sonnet.md`
- ВСЕ JSON-вердикты critic по beats → `_critic_log_Glava_01_sonnet.json` (массив объектов: `{beat_id, iteration, verdict, flags, action}`)

Если Глава 1 уже написана с sonnet — JSON-вердикты должны быть в логах. Найти их и переименовать в `_critic_log_Glava_01_sonnet.json`.

### Шаг 3. Прогон B (opus — эксперимент)

1. В `.claude/agents/bf-critic.md` изменить `model: sonnet` → `model: opus`. Добавить в frontmatter временную пометку:
   ```yaml
   experiment: "2026-05-08 critic model comparison; rollback after Глава 01 done"
   ```
2. Запустить writer-loop на Главе 1 ЗАНОВО (тот же beat_plan, тот же compiled session). Сохранить:
   - Финальный draft → `Glava_01_KS_draft_opus.md`
   - JSON-вердикты → `_critic_log_Glava_01_opus.json`

### Шаг 4. Откат

Восстановить `.claude/agents/bf-critic.md` из backup'а: `model: sonnet`, без `experiment:` поля. Удалить backup-файл.

### Шаг 5. Сравнительный отчёт

Создать `_critic_comparison_2026-05-08.md`:

**Метрики:**
- Количество beats: всего / accepted с первого раза / revise / rewrite — для каждой модели.
- Количество итераций на главу: суммарно для каждой модели.
- Среднее число флагов на beat.

**Качественный анализ (по 3 случайным beats и 3 beats с расхождением вердиктов):**
- Какие флаги поставил sonnet, какие opus.
- Какая модель поймала: повтор сквозных формул из Главы 0, паттерн «Не X. Y.», слабую атрибуцию, грамматические тонкости голоса.

**Стоимость:**
- Примерные токены на входе/выходе для каждой модели по логам.

**Финальный draft:**
- Беглый ручной читаемый разбор: где `Glava_01_KS_draft_opus.md` лучше/хуже `Glava_01_KS_draft_sonnet.md`. Не править — только наблюдения.

**Рекомендация:** sonnet / opus / гибрид (sonnet для structural, opus для voice-проверок) — с обоснованием.

### Шаг 6. Фиксация

Обновить `_SESSION_STATE.md` (новая запись сверху): результат эксперимента, путь к отчёту, рекомендация модели для оставшихся глав KS.

**НЕ менять** model в `bf-critic.md` без явного решения автора по результатам отчёта.

## Триггеры остановки

- Если backup или подмена модели не удалась — остановиться, отчитаться.
- Если opus-прогон занимает >2× времени sonnet-прогона — отчитаться, не ждать завершения.
- Если результаты драфтов opus и sonnet идентичны на первый взгляд — отчитаться, эксперимент незачем продолжать в полном объёме.
