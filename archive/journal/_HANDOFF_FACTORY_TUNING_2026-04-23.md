## 1. КОРНЕВАЯ РАЗВИЛКА — ДВА WORKFLOW-А

Фабрика обслуживает **два** режима работы. Это фундаментальное разделение, которое отсутствует в текущем `BooksFactory/CLAUDE.md` (там написано «для серии книг» — формулировка **некорректна**, должно быть «для серии и для отдельных книг, создаваемых на фабрике и переделываемых из внешних»).

### Workflow A — «С нуля» (книга/глава, которой ещё нет)

```
Agent 1: Ресёрчер/Планировщик        (Opus)
        ↓ outline → [одобрение]
        ↓ литература + арены
Agent 2: Автор MATERIAL               (Opus — «маленький писатель»)
        ↓ per-глава MATERIAL
Agent 3: Компилятор Session           (Sonnet — только bash/cp/sed)
        ↓ Session = MATERIAL + T1 + T2–T12 (из шаблона книги)
Agent 4: Writer                       (Opus)
        ↓ draft главы на полный объём
Agent 5: Критик/Редактор              (Opus)
        ↓ editorial report (max 5 точек)
[одобрение] → правки → ...→ clean draft → Edit в реальный файл
Agent 6: Гуманизатор                  (по правилу языка)
Agent 7: Переводчик                   (если нужен)
```

**Ключ:** Agent 2 творческий (Opus), от его MATERIAL зависит качество Writer-а. Agent 3 — чисто механическая сборка (Sonnet): `cp` MATERIAL + подстановка T1 + `sed` протокол. **Никаких переписываний руками.**

### Workflow B — «Переделка внешней книги» (написана НЕ на фабрике)

```
Agent Entry: Editor-Lite              (проверь скилл в фабрике!)
        ↓ проверка на спотыкания читателя + «проч. херню»
        ↓ ВЕРДИКТ: читабельно / нет + карта дефектов
        ↓ артефакт типа Buch_N_Edit.md
[одобрение автора]
        ↓
Компилятор: TZ на переделку            (Session-like — имя на усмотрение)
        ↓
Далее — Writer/Критик/Гуманизатор по Workflow A, начиная с Writer.
```

**Живой пример артефакта Editor-Lite:** `_testing/03_Manipulationen/Buch_3_Edit.md`. Это **образец**, что Editor-Lite должен уметь выдавать.

### Workflow C — «Редактура главы, написанной на фабрике»

Классический фабричный цикл Writer↔Editor (уже описан в `CLAUDE.md`). Не трогать.
