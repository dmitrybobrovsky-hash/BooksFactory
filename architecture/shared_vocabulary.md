# BooksFactory — Общий словарь

## Правило использования

**Термин определяется один раз — здесь.** Все остальные документы ссылаются: «см. `shared_vocabulary.md`». Нельзя давать собственное определение термина, уже зафиксированного в этом файле.

**Диагностический вопрос для нового термина**: «Применимо ли это ко всем книгам проекта?» — если да, сюда; если нет — в словарь конкретной книги.

---

## 1. Производственная цепочка

```
Исследователь → Сборщик материала → Планировщик → Сборщик задания → Координатор (writer-loop) → Редактор → Гуманизатор
```

Агенты: `bf-researcher` → `bf-material-author` → `bf-planner` → `bf-compiler` → `bf-coordinator` (включает `bf-writer` + `bf-critic` + `bf-controller`) → `bf-editor` → `bf-humanizer` → ``.

Роли работают последовательно. Артефакт, не прошедший контракт роли, **возвращается на предыдущую роль** — не исправляется текущей. Контракты: `architecture/handoff_contracts.md`.

## 2. Единицы структуры текста

| Термин | Определение | Не путать с |
|--------|-------------|-------------|
| **глава** | Единица чтения. Собирается из нескольких секций. Один MATERIAL-файл, один Session-файл. | Секция — единица письма, часть главы. |
| **секция** | Единица письма. H2-блок внутри главы. Пишется за один проход. Имеет собственный микрорежим и beat sheet. | Глава — собирает секции в единицу чтения. |
| **beat** | Микро-ход внутри секции. Один конкретный ментальный шаг читателя: диагностический удар, заземление, разворот, парадокс, замыкание. Каждый beat имеет word budget. | Такт в музыке — только ритм. Beat — смысловой ход с конкретной функцией. |
| **beat sheet** | Список 5–7 beats для одной секции, каждый с word budget. Управляет секцией против раздувания. Пример: «диагностическая посылка — 200 слов / заземляющая сцена — 300 слов». Создаёт Сборщик материала (`bf-material-author`), уточняет Планировщик (`bf-planner`), потребляет Писатель (`bf-writer`). | Outline главы — крупнее, без word budgets. Beat sheet — уровень секции. |

### Формат заголовков секций в контенте книги

В тексте глав (всё, что видит читатель — `Glava_NN_*_draft.md`, `_clean.md`, `_humanized.md`, `_<LANG>.md`) **заголовки секций оформляются числовой нумерацией с точкой**, без знака `§`.

✅ Правильно:
```markdown
## 1. Зачем нужен образ там, где есть слова
## 2. Что отличает организационный МАК от клинического
## 3. Кому эта книга
## 4. Устройство книги
```

❌ Запрещено:
```markdown
## §1 Зачем нужен образ...
## § 1. Зачем нужен образ...
```

**Обоснование:** знак `§` — юридическо-нормативный (статьи законов, параграфы кодексов). В книгах для практиков создаёт ложный регистр инструктивно-правового текста, противоречащий принципу 1 серии («читатель — коллега, не подсудимый»). Применяется только в служебной нотации фабрики (контракты в `handoff_contracts.md`, self-check разделы в агентах) — там это технически оправдано как «параграф документа».

**Кого касается:**
- `bf-material-author` — при формировании MATERIAL и beat-sheets использует нумерацию `## N. Название` для будущих секций
- `bf-writer` — при письме secции воспроизводит формат заголовка по beat_plan
- `bf-compiler` — при сборке Session не вносит `§`
- `bf-editor` — при clean-passe проверяет: если в главе есть `## §N`, это нарушение T-правила оформления (точка отчёта, не летальная — точечная правка заголовков)
- `bf-humanizer` — не меняет заголовки (не его зона)

**Книги, написанные до введения правила (2026-05-10):** Test3 KS Главы 0–1 содержат `§N` в существующих артефактах. При production-выкатке этих глав — выполнить точечную замену `## §N → ## N.` как часть финальной правки.

**Источник правила:** решение автора 2026-05-10 после smoke-test Главы 0 KS.

## 3. Производственные документы

### 3.1 Слой A — per-book (собирается PM-research один раз на книгу)

| Термин | Определение | Где живёт |
|--------|-------------|-----------|
| **anweisungen** | Операционная инструкция книги: идентичность автора, протокол написания, naming convention, абсолютные запреты. | `<book>/anweisungen_XX.md` |
| **stil_und_ton** | Голос, тональные параметры, эскалация по частям, лексический контроль, запреты. Заменяет старый `tonal_compass.md` на уровне книги. | `<book>/stil_und_ton_XX.md` |
| **arbeitsplan** | Полный план книги: вступление + части × главы + заключение, тезисы каждой главы. Основа для генерации MATERIAL-блоков. | `<book>/arbeitsplan_XX.md` |
| **quellen_pool** | Источники под каждую главу (предсобранные, для копипаста в MATERIAL-блок). | `<book>/quellen_pool_XX.md` |
| **arenen_pool** | Репозиторий арен + Cool-Down + матрица распределения по частям. | `<book>/arenen_pool_XX.md` |
| **`<technique>`** | **Обязательный слот:** книжная фишка (например `street_calibration_XX.md`). Одна книга = одна ведущая техника. | `<book>/<technique>_XX.md` |
| **session_template** | Технический протокол T2–T12 книги — статическая часть Session, одинаковая для всех глав этой книги. | `<book>/session_template_XX.md` |
| **abgrenzung** | Отграничения от остальных томов серии. **Обязателен только для книги в серии**; для standalone — не требуется. | `<book>/abgrenzung_XX.md` |

### 3.2 Слой B — per-chapter

| Термин | Определение | Где живёт |
|--------|-------------|-----------|
| **MATERIAL-блок** | Beat sheet одной главы: структура секций с целевыми объёмами, микрорежим каждой секции, арены главы, источники главы. Не самостоятельный файл, а верхняя часть Session. Производит: PM. | блок внутри `Session_KapitelNN.md` |
| **Session** | **Единственное ТЗ для Писателя.** Самодостаточный файл = MATERIAL-блок (что писать) + T1 (уникальные поля главы) + T2–T12 (статический техпротокол из `session_template_XX.md`). Склеивается побайтовым копированием, не переписывается. | `<book>/Session_KapitelNN.md` |
| **handoff** | Момент передачи артефакта от одной роли к следующей по цепочке. Формат передачи и критерии возврата: `architecture/handoff_contracts.md`. | — |

**Правило для Писателя:** читать только `Session_KapitelNN.md`. Никаких обращений к `anweisungen`, `stil_und_ton`, пулам — всё уже впечено в Session при сборке.

## 4. Тональные концепции

| Термин | Определение | Примечание |
|--------|-------------|------------|
| **микрорежим** | Тональный регистр секции. Назначается PM в MATERIAL. Примеры: «ледяная клиническая фиксация», «горькая усмешка», «анатомическая точность», «Street-Calibration», «тихая констатация». | Полный список — в тональной карте конкретной книги. BooksFactory фиксирует принцип, не список. |
| **тональная карта** | Документ конкретной книги: регистр, микрорежимы, запреты, намеренные приёмы. Override для дефолтных правил любой роли BooksFactory. | `<book>/skills/writer-<book>/references/tonal_compass.md` |
| **арена** / **Street-Calibration** | Сцена, заземляющая тезис в телесном или сенсорном опыте читателя. Конкретный наблюдаемый момент, не абстракция. Researcher назначает в arenen_pool, material-author берёт как есть. | Арена ≠ пример. Арена — телесная, наблюдаемая. Пример — концептуальный. Правило: ровно 3 арены на каждую главу. Три интенсивности: высокая + средняя + низкая. Введение и Заключение — на усмотрение researcher-а с обоснованием и согласованием с автором. |
| **декомпрессия** | Пауза после арены. Форма: немота / констатация / неодушевлённая деталь. Не резюме, не вывод — дыхательный момент после удара. | Типовая ошибка: ставить вывод вместо декомпрессии. |
| **сигнатурная фигура** | Устойчивая риторическая конструкция голоса автора. Для серии: «не потому что X — а потому что Y» (RU) / «nicht weil X — sondern weil Y» (DE). Лимит: не более 8 на главу. При переводе сохраняется структурно, не дословно. | Превышение лимита (>8/глава) превращает сигнатуру в тик.  Per-chapter лимит: ≤8. Cross-chapter ориентир: ≤50 на книгу; счётчик в continuity-блоке MATERIAL. |

### 4.1. Иерархия голоса (приоритет при конфликте)

Три уровня источников голоса. При расхождении побеждает уровень с бо́льшим номером (книга > серия > фабрика).

| Уровень | Документ | Что фиксирует | Где живёт |
|---------|----------|---------------|-----------|
| 1. Фабрика (дефолт) | голосовые правила фабрики | Общие правила голоса и запреты — применимы ко всем книгам. | rchitecture/shared_vocabulary.md §3 |
| 2. Серия (если есть) | серийный канон книги | Терминология, инварианты обращения к читателю, кросс-книжные правила (повторяющиеся термины, общие запреты). | ook_config.json → series.bible_path |
| 3. Книга | `tonal_compass.md` (он же `stil_und_ton_XX.md` в новой модели слоя A — см. §3.1) | Голос конкретной книги, её регистр, микрорежимы, эскалация по частям, override-правила. | `<book>/tonal_compass.md` или `<book>/stil_und_ton_XX.md` |

**Правило конфликта**: книжный 	onal_compass/stil_und_ton > серийный > фабричный. Книга добавляет микрорежимы, серия фиксирует кросс-книжные инварианты (например, обращение «ты»/«du»), фабрика — общий дефолт.

**Где это проверяется**: Редактор при работе с главой читает все три уровня и фиксирует расхождения как failure mode «нарушение приоритета голоса». Писатель полагается на Session — туда уже впечён актуальный голос (T1–T4 собирает Compiler).

## 5. Контроль качества

| Термин | Определение | Где подробнее |
|--------|-------------|---------------|
| **failure mode** | Повторяющаяся ошибка рукописи: код, описание, маркеры обнаружения, стратегия исправления. Ловит Редактор. | `<book>/skills/editorial-<book>/references/failure_modes.md` |
| **ИИ-отпечаток** | Маркер машинного происхождения текста. Три категории: лексические штампы (~120 единиц, 3 яруса), структурные антипаттерны (30 конструкций), языковая специфика (кальки, синтаксические клише). Удаляет Гуманизатор. | `skills/humanizer/ru/references/` |
| **раздувание** | Состояние секции: число содержательных утверждений на 100 слов упало ниже порога плотности. Причины: возвраты к сказанному, переформулирование тезиса, безопасные прилагательные, избыточные уточнения. | `architecture/writing_control.md` |
| **реинтродукция** | Текущая роль случайно вносит ошибку, которую должна ловить предыдущая роль. Пример: Гуманизатор вносит failure mode, уже убранный Редактором. Правило: кто внёс — тот и исправляет немедленно, без возврата. | `skills/humanizer/ru/SKILL.md`, раздел «Самопроверка» |
| **пост-контроль** | Проверка плотности секции после написания. Если ниже порога — секция раздута, удалять воду, не переписывать. | `architecture/writing_control.md` |

## 7. Кросс-книжные запреты

Применимы к любой книге серии, любому языку. Не перечисляются повторно в скиллах ролей — только ссылка сюда.

| Запрет | Причина |
|--------|---------|
| Обращение «вы» (RU) / «Sie» (DE) к читателю | Дистанция убивает голос. Только «ты» / «du» / «you». |
| Симметричная аргументация («истина посередине») | Маркер ИИ. Автор имеет позицию — не «балансирует». |
| Коучинговый тон («ты можешь», «начни сегодня») | Нарушает регистр. Автор показывает, не поучает. |
| Мотивационная риторика | То же. |
| Демонизация читателя | Субъект провокации — система / механизм / инерция мышления, не читатель. |
| «Паттерн» в рукописных текстах более 2 раз на главу | Ротация: механизм, реакция, привычка, ответ, рефлекс, схема, контур, маршрут. |
| Любое специфическое слово более 2 раз на главу | Замены должны быть разными, не одним словом-синонимом. |

**bibliography_mode** — формат оформления источников в книге. Задаётся АВТОРОМ в брифе, не агентом. Researcher фиксирует в anweisungen_XX.md без изменений. Два значения:
- per-chapter (автор пишет: «источники в каждой главе») — раздел «Для дополнительного изучения» в конце каждой главы.
- unified (автор пишет: «источники в конце книги») — один раздел «Для дополнительного изучения» в конце книги. Ссылки внутри глав на источники не делаются.
Выдумывать источники ради заполнения объёма запрещено. Вставлять нерелевантные или интернет-ссылки ради количества запрещено.
