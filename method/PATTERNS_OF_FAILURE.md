# Каталог Паттернов Отказа — BooksFactory

> Эти ошибки уже случились. Каталог существует, чтобы они не случились в следующий раз.

---

## Уровень 1: Голос

### FP-V1 — Демонизация

**Код**: FP-V1 (Voice / Demonization)  
**Книги**: ОНМ (Части II–III — доминирующий failure mode)

**Признаки**:
- Персонаж описывается через исключительно негативные атрибуты без нюансов
- Исчезают механизмы — остаются ярлыки
- Глаголы: «манипулирует», «разрушает», «уничтожает» — без контекста и ограничений

**Маркеры grep**:
```
всегда (в связке с негативным действием)
никогда не испытывает
только разрушает
```

**Диагностический вопрос**: «Есть ли в этой главе хотя бы одно утверждение, снижающее обвинение?»

**Контроль**: Редактор, отдельный pass по Частям II–III

---

### FP-V2 — Sympathy Leak

**Код**: FP-V2 (Voice / Sympathy Leak)  
**Книги**: ОНМ (Части IV–V)

**Признаки**:
- Тон смягчается в сценах «человеческого» поведения персонажа
- Глаголы заменяются на более мягкие аналоги
- Появляются объяснения, снимающие ответственность

**Маркеры**:
```
всё-таки (в оправдательном контексте)
по-своему
в глубине души
```

**Диагностический вопрос**: «Изменился ли тон глагола по сравнению с нейтральной главой?»

**Контроль**: Editor — каждая сцена с «человеческим» поведением персонажа

---

### FP-V3 — Симметричная аргументация

**Код**: FP-V3 (Voice / Symmetry)  
**Книги**: ОНМ (Часть I)

**Признаки**:
- «С одной стороны... с другой стороны»
- Контраргумент добавлен для «баланса», не для разбора
- Автор исчезает, остаётся «честное перечисление»

**Маркеры**:
```
с другой стороны
некоторые исследователи считают (без опровержения)
можно возразить
```

**Контроль**: Contract 2 (Writer→Editor) — отдельный пункт

---

### FP-V4 — Коучинговый тон

**Код**: FP-V4 (Voice / Coaching Drift)  
**Книги**: ОНМ (сквозной, особенно после сложных секций)

**Признаки**:
- Автор начинает «помогать» читателю вместо того, чтобы вести
- Появляются мягкие предложения вместо утверждений
- Тон: «можете попробовать», «стоит обратить внимание»

**Маркеры**:
```
важно помнить
стоит обратить внимание
позвольте предложить
можете попробовать
обратите внимание
```

**Контроль**: Pass 2 гуманизатора — коучинговый список отдельно от ИИ-маркеров

---

### FP-V5 — Академический дрейф

**Код**: FP-V5 (Voice / Academic Drift)  
**Книги**: ОНМ (Часть I), потенциально любая книга серии

**Признаки**:
- Текст начинает звучать как научная статья
- Пассивные конструкции нарастают
- Абзацы заканчиваются на «таким образом», «следовательно», «можно заключить»

**Маркеры**:
```
таким образом
следовательно
можно заключить
данное явление
представляет собой
```

**Контроль**: verbot_liste книги (антипаттерны голоса); Editor проверяет opening и closing каждого абзаца

---

## Уровень 2: Содержание

### FP-C1 — Абсолютные утверждения

**Код**: FP-C1 (Content / Absolutes)  
**Книги**: ОНМ (Часть I — особенно высокий риск)

**Признаки**:
- «Все X делают Y»
- «Никогда не бывает Z»
- Утверждения без квалификации о частотности или контексте

**Диагностический тест**: «Читатель с одним контрпримером — закрывает книгу?»

**Контроль**: Editor — Часть I читается отдельным passes под FM-Q1

---

### FP-C2 — Отсутствующий контраргумент (не путать с FP-V3)

**Код**: FP-C2 (Content / Missing Counterargument)  
**Книги**: ОНМ (Часть I)

**Разница от FP-V3**: Здесь контраргумент нужен для точности, не для «баланса». Он включается — и немедленно разбирается.

**Признаки**:
- Утверждение, которое имеет известные исключения — исключения не упоминаются
- Читатель, знакомый с полем, видит неточность

**Контроль**: PM при исследовании фиксирует контраргументы в MATERIAL. Писатель включает — и разбирает.

---

## Уровень 3: Структура

### FP-S1 — Технический межглавный мостик

**Код**: FP-S1 (Structure / Technical Bridge)  
**Книги**: ОНМ (главы 4, 5, 6, 7, 8, 9, 12)

**Признаки**:
```
В следующей главе мы рассмотрим...
Теперь обратимся к...
В этой главе речь пойдёт о...
```

**Механизм**: Писатель не получил образец литературного перехода → дефолт технический.

**Контроль**: Session T4 содержит пример закрытия + тип открытия следующей главы.

---

### FP-S2 — Дублирующийся closing

**Код**: FP-S2 (Structure / Duplicate Closing)  
**Книги**: MdP (Kapitel 6 и 7: «Und jetzt dein Büro.»)

**Признаки**:
- Последнее предложение / последний абзац главы совпадает с другой главой книги
- Удар, сработавший однажды, используется как формула

**Контроль**: Editor grep последних 3 предложений каждой главы — сравнение по книге.

---

### FP-S3 — Раздувание секции

**Код**: FP-S3 (Structure / Section Bloat)  
**Книги**: ОНМ (диффузно), MdP (потенциально)

**Признаки**:
- Плотность < 4 утверждений на 100 слов
- Последнее предложение абзаца повторяет первое другими словами
- «Возврат к сказанному»: переформулировка без добавления смысла

**Контроль**: post-control после каждой секции (writing_control.md)

---

## Уровень 4: Лексика

### FP-L1 — Перенасыщение сигнатурной фигурой

**Код**: FP-L1 (Lexical / Signature Overuse)  
**Книги**: ОНМ (322 после cleanup), MdP Kapitel 3 (15 штук)

**Маркеры**:
- RU: «не потому что X — а потому что Y»
- DE: «nicht weil X — sondern weil Y»

**Лимиты**: ≤ 8 на главу (BooksFactory default); книга может снизить лимит в тональной карте.

**Контроль**: Writer post-control, Grep перед handoff

---

### FP-L2 — Монополия одного слова

**Код**: FP-L2 (Lexical / Word Monopoly)  
**Книги**: ОНМ («паттерн» 31→25, «тишина» 184, «молчание» 238)

**Механизм**: Точное слово найдено → ротация не происходит → читатель устаёт.

**Контроль**:
- «Паттерн»: ≤ 2 на главу, ротация из 6 замен
- Специфические слова книги: Grep после написания, лимит фиксируется в тональной карте

---

### FP-L3 — Лексическое обеднение через избыточные замены

**Код**: FP-L3 (Lexical / Synonym Fatigue)  
**Контекст**: Риск при активной работе гуманизатора

**Механизм**: Гуманизатор заменяет «паттерн» → одним словом («механизм») → теперь «механизм» появляется 25 раз.

**Контроль**: Реинтродукция-check Pass 3 гуманизатора. Замены — из ротационного списка, не из одного слова.

---

### FP-L4 — Синтаксическая несочетаемость замены

**Код**: FP-L4 (Lexical / Syntactic Mismatch)  
**Контекст**: При ручной или автоматической замене слов

**Примеры**:
- «петля запускается» → заменили «петля» на «сюжет» → «сюжет запускается» (не работает)
- «отключить паттерн» → «отключить механизм» (возможно), «отключить ответ» (нет)

**Контроль**: Проверять весь абзац вокруг замены, не только позицию замены.

---

## Уровень 5: Производство

### FP-P1 — Batch-изменение без backup

**Код**: FP-P1 (Production / No Backup)  
**Книги**: ОНМ (13 глав с потерей контента)

**Последствия**: Восстановление требует ручной сверки с SOS-бэкапами — часы работы.

**Контроль**: SOS backup перед каждым batch-инструментом. Обязательно, без исключений.

---

### FP-P2 — Дублирование аннотаций источников

**Код**: FP-P2 (Production / Duplicate Annotations)  
**Книги**: MdP (19 случаев)

**Механизм**: PM копирует блок источников из предыдущего MATERIAL → не обновляет фокус.

**Контроль**: Contract 1 — проверка уникальности фокуса каждого источника.

---

### FP-P3 — Статус-дрейф

**Код**: FP-P3 (Production / Status Drift)  
**Контекст**: Риск при работе с несколькими главами параллельно

**Механизм**: Глава переходит в следующую фазу без реального прохождения контракта → роль работает с материалом, который не готов.

**Контроль**: Статус проставляет только роль, завершившая контракт. Самодеклларация запрещена.
