# Сессия 9-L (локально, автономно, экономно) — глава 01

## Зачем
Полный цикл сессий 7–8 стоит ≈70 вызовов агентов на главу: каждый фрагмент, каждая правка и каждая проверка — отдельный агент, который заново читает роль и контекст. Эта сессия делает ту же главу за **8–10 вызовов агентов**: скрипты-проверки остаются (они бесплатные), а мелкую работу оркестратор делает сам, без запуска агентов. Результат — замер цены и качества для решения о режиме фабрики.

## Режим
Как в `_SESSION9_LOCAL.md` (автономия до финальной вычитки, реестр, ничего не удалять, не трогать главы 00 и 02–05 и правила, `python`, журнал). Журнал — **тот же** `_SESSION9_LOG.md`: если полная сессия 9 уже что-то сделала (архив старой главы, план, beat-ы) — **используй сделанное**, не переделывай; в журнале отметь переход на экономный режим. Workflow не используй.

**Бюджет — не больше 10 вызовов агентов на всю главу.** Всё остальное — сам оркестратор (Read/Edit/Write и скрипты).

## Шаги

**L0. Подготовка** — по `_SESSION9_LOCAL.md` («Подготовка»), если ещё не сделана.

**L1. План — 1 агент** (`bf-planner`, требования C1 из `_SESSION9_LOCAL.md` и `_SESSION8_CLOUD.md`). Если план уже есть и проверен — пропусти. Проверка плана — сам (как B2).

**L2. Текст — по одному агенту `bf-writer` (opus) на секцию** (обычно 5 вызовов). Перед вызовом сам сделай `slice_context.py` для каждого beat-а секции. Задание писателю: роль `.claude/agents/bf-writer.md`; контексты beat-ов секции (файлы); последний beat предыдущей секции — для стыка; журнал главы (реквизит и тезисы уже написанного — веди сам в `B/_work/01/ledger.json`); написать **все beat-ы секции по порядку**, каждый в свой файл `B/01_beats/beat_N.md`, только проза.
После секции — `lint_beat.py` по каждому beat-у (скрипт). Нарушения (`hard_flags`) и мелкие огрехи **исправляешь сам** через Edit, точечно; агента повторно не зовёшь. Обнови журнал главы.

**L3. Глава целиком — без агентов.** Сборка предпросмотра, `lint_chapter.py` (потолок 6000, бюджет антитез 8, лимиты плана). Сам читаешь главу целиком и правишь: превышения из `problems`, повторы мысли между beat-ами, служебные мосты, слияние реквизита разных сцен, неподтверждённые утверждения об исследованиях. Повторный `lint_chapter` — `problems` пусто. Сборка `Glava_01_KS_draft.md`, статус `draft`.

**L4. Редактор — 1 агент** (`bf-editor`, opus; задание как в B6 сессии 7 + проверка стыков с введением и главой 02). Отчёт `B/Glava_01_KS_editor_report.md`, статус `review`. Все точки и микроправки **вносишь сам** (Edit), выбор по умолчанию — в реестр; сборка, `lint_chapter` — пусто.
Второй вызов редактора (только проверка закрытия точек высокого веса, модель sonnet) — **только если** в отчёте были точки высокого веса. Иначе — `clean` по итогам твоей сверки точка-за-точкой (запиши в журнал, как закрыта каждая). Статус `clean`, заморозка `Glava_01_KS_clean.md` (`total_words` — по скрипту).

**L5. Гуманизация — 1 агент** (`bf-humanizer`, opus; рамки A3 сессии 7). Контроль — сам: скрипт (как A4: антитезы ≤ 8, объём −8…+1 %, verbot, заголовки) и твоё сравнение чистовика с результатом по абзацам (смысл, цитируемые образы, вернувшиеся дефекты редактора). Найденное — исправляешь сам точечно. Статус `humanized`, `total_words` — по скрипту.

**L6. Финал — без агентов.** Реестр: раздел «Глава 01». Отчёт `_SESSION9_LOCAL_REPORT.md`: §1 для автора (3–4 строки, без вопросов); **§2 замер** — вызовов агентов по ролям, время начала/конца, сравнение с главами 03–05 (вызовы, итоговый объём, антитезы, итерации редактора); §3 решения без автора. Числа отчёта сверь скриптами сам. Запись в `B/_SESSION_STATE.md`. Автору — одна строка: «Готово, отчёт в папке фабрики».
