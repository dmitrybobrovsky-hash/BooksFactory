# BooksFactory — Управление раздуванием (Writing Control)

## Центральная проблема

**Диагноз**: Писатель пишет 900 слов органического текста, потом начинает раздувать до целевого объёма секции. Симптомы: возвраты к уже сказанному, переформулирование тезиса разными словами, безопасные прилагательные, уточнения уточнений.

**Следствие**: секция в 2000 слов содержит 900 слов содержания и 1100 слов воды. Читатель чувствует это ещё до сознательного анализа.

**Решение**: управлять секцией через beat sheet — список конкретных микро-ходов с word budgets, — а не через целевой объём. Когда каждый beat задан конкретной задачей и бюджетом, Писатель заполняет задачи, а не растягивает.

Термины: см. `architecture/shared_vocabulary.md`.

---

## Правило 1: Секция — единица письма, не глава

Раздувание возникает на уровне **секции** (H2-блок), не главы. Поэтому:

- Управляющий инструмент — beat sheet **секции**, не outline главы
- Контроль плотности — **после каждой секции**, не после главы
- Целевой объём задаётся **на секцию**, не суммарно

**Практически**: PM создаёт отдельный beat sheet для каждой секции в MATERIAL. Писатель пишет секцию за секцией, не пытаясь «набрать» объём главы.

## Правило 2: Beat sheet управляет секцией

### Структура beat sheet

```
## Секция N: [Название]
Целевой объём: XXXX слов
Микрорежим: [название режима]

Beat sheet:
1. [Название beat] — XXX слов — [задача: что должен сделать этот beat]
2. [Название beat] — XXX слов — [задача]
3. [Название beat] — XXX слов — [задача]
4. [Название beat] — XXX слов — [задача]
5. [Название beat] — XXX слов — [задача]
```

### Пример beat sheet для секции 2000 слов

```
## Секция 2: Лояльность из страха
Целевой объём: 2000 слов
Микрорежим: анатомическая точность

Beat sheet:
1. Диагностическая посылка — 200 слов — назвать механизм без объяснения, создать натяжение
2. Заземляющая сцена (ARENA-07) — 350 слов — телесный момент: офис после увольнения
3. Декомпрессия — 60 слов — неодушевлённая деталь, не вывод
4. Микроанатомия механизма — 550 слов — три компонента страха как управляющей силы
5. Парадокс внутри механизма — 400 слов — почему лояльный сотрудник опаснее нелояльного
6. Контраргумент и его разоблачение — 240 слов — «он мог уйти» → почему это не работает
7. Замыкающий удар — 200 слов — одна фраза, остающаяся после прочтения
```

### Типы beats (не исчерпывающий список)

| Beat | Функция | Типичный объём |
|------|---------|----------------|
| Диагностическая посылка | Назвать явление без объяснения, создать натяжение | 150–250 слов |
| Арена / Street-Calibration | Телесное заземление тезиса | 250–400 слов |
| Декомпрессия | Дыхательная пауза после арены | 40–80 слов |
| Микроанатомия | Разбор механизма по компонентам | 400–700 слов |
| Парадокс | Разворот, ломающий ожидаемую логику | 300–500 слов |
| Контраргумент + разоблачение | Честный ввод возражения и его деструкция | 200–350 слов |
| Замыкающий удар | Последняя фраза секции, остающаяся в голове | 100–200 слов |
| Тихая констатация | Голый факт без комментария | 50–120 слов |

## Правило 3: Запреты при написании секции

Каждый из этих паттернов — маркер раздувания. Писатель проверяет по чеклисту после написания секции.

| Запрет | Пример нарушения | Почему это вода |
|--------|-----------------|----------------|
| Возврат к уже сказанному | «Как мы уже отмечали выше...», «Как было показано...» | Повторяет, не добавляет |
| Переформулирование тезиса | Та же мысль, другими словами, без нового угла | Читатель уже понял |
| Безопасные прилагательные | «важный», «значительный», «существенный», «ключевой» без спецификации | Пустое усиление |
| Уточнение уточнений | «Иными словами, это означает, что...» после уже ясного предложения | Снисхождение к читателю |
| Бесплатное обобщение | «Всё это говорит о том, что...» в конце секции, которая уже говорит сама | Костыль вместо удара |
| Симметричное закрытие | «С одной стороны... с другой стороны...» как итог секции | Уход от позиции |

## Правило 4: Пост-контроль плотности

После написания секции — проверка перед переходом к следующей.

### Метрика плотности

**Содержательное утверждение** — предложение, которое несёт уникальный факт, аргумент, наблюдение или парадокс. Предложения-связки, пустые переходы, прилагательные-усилители — не считаются.

**Порог**: не менее **4 содержательных утверждений на 100 слов** (допустимо ниже в декомпрессии и арене).

### Процедура пост-контроля

1. Перечитай секцию. Подсчитай содержательные утверждения в случайных 300 словах.
2. Если < 4/100 → секция раздута. Переходи к шагу 3.
3. **Удаляй воду, не переписывай**: найди предложения, которые повторяют уже сказанное — удаляй их, не заменяй синонимами.
4. Проверь, не образовались ли «швы» после удаления. Если да — пиши мост (1–2 предложения), но не объясняй удалённое.

### Grep-проверка повторов

Найди существительные, несущие один и тот же смысл в трёх абзацах подряд — это маркер раздувания. Исправление: удали повторяющийся абзац, не паресмысли его.

**Команда в Редакторе (bash)**:
```bash
# Проверка повторяющихся существительных в соседних абзацах
grep -c "СЛОВО" glava.md
```

Этот файл — кросс-книжный. Специализированные правила для конкретной книги (целевые объёмы секций, типичные beats для жанра) живут в:

## Правило 6: Умолчания по объёму главы

Фабричные дефолты на случай, когда в книге не задан явный override:

| Тип главы | Целевой объём (максимум) |
|-----------|--------------------------|
| Обычная глава | **до 6000 слов** |
| Введение | **3500–3700 слов** |
| Заключение | **3500–3700 слов** |

Эти значения — **потолок после редактуры**, не цель Писателя. Writer в режиме Draft Fat пишет до 1.1–1.2× от потолка; Editor срезает до потолка (King's «2nd Draft = 1st Draft − 10%»).

### Override-механика

- **Per-книга override** → `<book>/tonal_compass.md` (если у книги другой жанр / плотность / целевой читатель).
- Fallback: <book>/_workdir/tonal_compass.md. Путь к книге — из ook_config.json.
- **Per-глава override** → поле `target_words` в MATERIAL главы (через PM при создании MATERIAL).
- Если override-а нет — применяется фабричный дефолт из таблицы выше.

### Почему именно эти числа

Диагностическая проза на немецком при плотности ≥4 содержательных утверждений на 100 слов (Правило 4) выдаёт органически ~5500–6000 слов на главу без раздувания. Выше — начинается вода или топтание. Введение и заключение структурно короче: они несут позицию, не развёртывают механизм.

Целевые объёмы **секций** внутри главы определяются beat sheet-ом (Правило 2), не делением 6000 / количество_секций.

## Антипаттерны PM при создании beat sheet

| Антипаттерн | Почему плохо | Как правильно |
|-------------|-------------|---------------|
| Beat без задачи: «Основная часть — 500 слов» | Писатель не знает, что именно делать в этих 500 словах | «Микроанатомия механизма страха — 500 слов: три компонента, каждый с примером» |
| Beat sheet из 2 beats | Слишком крупные куски — Писатель неизбежно раздует | Минимум 5 beats на секцию > 800 слов |
| Один beat на всю секцию 3000 слов | Нет шва, нет ворот | Разбить на 6–8 beats, каждый max 500 слов |
| Beat «введение» | Введения раздуваются первыми | Заменить на конкретный первый ход: «Диагностическая посылка» |
| Beat «заключение» | Типичный ИИ-закрытие | Заменить на «Замыкающий удар» с конкретной функцией |
