# Case Protocol: «Карты на стол»
_Книжная техника: «Карта в действии — кейс → протокол»_
_Код книги: KS | Версия: 1.0 | Дата: 2026-05-05_

---

## Суть техники

Каждый раздел о карте или категории открывается фрагментом реальной сессии — коротким, конкретным, с физиологическим якорем. Принцип не объявляется заранее: он **обнаруживается** читателем из кейса. После кейса — пауза (одно-два предложения), затем механизм и протокол.

Порядок: **кейс → пауза → принцип → протокол**.

Не «сначала теория, потом пример». Практика объясняет теорию, а не иллюстрирует её.

---

## Цель техники

Книга о МАК рискует стать справочником — списком карт с описаниями. Case_protocol_KS разрывает этот сценарий: читатель-практик сначала встречает узнаваемую ситуацию из практики, потом понимает механизм. Узнавание предшествует объяснению — так протокол запоминается через опыт, а не через запоминание.

Дополнительный эффект: кейс создаёт доверие к позиции автора. Не «психология утверждает, что...», а «вот что происходит в комнате — и вот почему».

## Структура одного case_protocol блока

```
[КЕЙ С — 150–250 слов]
Конкретный момент сессии: один фасилитатор, один участник или группа,
одна карта, одна реакция. Без обобщений. Без вывода в конце кейса.
Физиологический якорь обязателен.

[ПАУЗА — 1–2 предложения]
Короткая констатация или вопрос без ответа. Не резюме — зазор перед
принципом.

[ПРИНЦИП — 100–200 слов]
Механизм, который объясняет кейс. Называется прямо. Ссылка на
теоретическую базу — в одном предложении, без разворота.

[ПРОТОКОЛ — маркированный список или нумерованные шаги]
Конкретные действия фасилитатора. Формат: шаг / вопросы для работы /
красные флаги (что указывает, что ситуация вышла за пределы инструмента).
```

---

## Формат применения в главах

| Контекст | Формат |
|----------|--------|
| Ключевая карта (2–3 на главу Части II) | Полный case_protocol блок: кейс + пауза + принцип + протокол |
| Компактная карта (остальные в главе) | Сокращённый формат: micro-кейс (50–80 слов) + протокол (без явного принципа) |
| Теоретическая глава (Часть I) | Кейс открывает главу или ключевой раздел; принцип разворачивается в основном тексте |
| Протокольная глава (Часть III) | Кейс открывает расклад или сценарий; протокол — развёрнутый, со step-by-step |

---

## Частота

- **Часть I (гл. 1–5):** 1 case_protocol на главу (открывает основной тезис) + 1–2 micro-кейса в теле главы.
- **Часть II (гл. 6–12):** 2–3 полных case_protocol на главу (ключевые карты) + micro-кейсы для компактных карт.
- **Часть III (гл. 13–15):** 1 полный case_protocol на расклад или сценарий (открывает блок), затем протокол.

Техника присутствует в каждой главе. Исключение: Введение и Заключение — там кейс может быть, но протокол не обязателен.

## Запреты

| Запрет | Почему |
|--------|--------|
| Объявлять принцип до кейса | Нарушает механику узнавания: читатель ждёт подтверждения, а не открытия |
| Обобщать внутри кейса | «Такое часто бывает» — выход из конкретики в абстракцию. Кейс остаётся одним моментом. |
| Делать кейс анонимным шаблоном | «Однажды клиентка Н. пришла на сессию...» — не кейс, а анекдот. Ситуация конкретна, не персонаж. |
| Заканчивать кейс выводом | Кейс обрывается на якоре — вывод делает читатель, принцип приходит после паузы |
| Протокол без красных флагов | Красные флаги — встроены, не в отдельном разделе. Каждый протокол содержит условие применения и условие остановки. |
| Более одного принципа на блок | Один кейс → один принцип → один протокол. Если нужен второй принцип — новый блок. |
| Кейс длиннее 250 слов | Кейс — удар, не история. Длинный кейс теряет якорь. |

## Связь с арен-пулом

Кейсы case_protocol строятся на аренах из `arenen_pool_KS.md`. Material-author берёт арену, назначенную для конкретной главы, и разворачивает её в сценарий сессии. Арена — сырьё, кейс — проза.

Writer не изобретает арены самостоятельно: если арена для главы указана в arenen_pool — использует её. Если нужна дополнительная — запрос к material-author, не импровизация.
