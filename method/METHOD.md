# Производственный цикл BooksFactory — End-to-End

> Артефакт движется по цепочке. Роль не владеет текстом — роль выполняет контракт и передаёт дальше.

---

## Входная точка: Решение написать главу

Триггер: PM получает задание (или книга требует следующую главу по структуре).

**Что должно существовать до запуска PM:**
- серийный канон (если книга в серии) — обновлён и актуален
- `_outline.md` книги — утверждён
- Тональная карта книги (`tonal_compass.md`) — создана

Если чего-то нет → PM создаёт недостающее **до** начала работы над MATERIAL.

---

## Фаза 1: Препродакшн (PM)

### 1.1 Контекстный запуск

PM читает:
1. `architecture/shared_vocabulary.md` — терминология фабрики
2. Серийный канон (если книга в серии) — серийный контекст
3. `tonal_compass.md` книги — микрорежимы, запреты, разрешения
4. `_outline.md` — место главы в структуре
5. Калибровочные главы (предыдущая + одна из эталонных)

### 1.2 Исследование

PM ищет источники: WebSearch, WebFetch.

Критерий отбора: источник должен давать механику (не только статистику), быть верифицированным, иметь конкретный фокус для этой главы.

### 1.3 MATERIAL

PM создаёт `MATERIAL_Glava_NN.md`:

| Поле | Требование |
|------|-----------|
| `глава`, `название`, `целевой_объём` | Обязательно |
| Структура секций | Каждая секция: название, объём, микрорежим |
| Beat sheet каждой секции | 5–7 beats с объёмами и задачами |
| Источники | Автор, название, год, фокус для этой главы |
| Открытые вопросы для Писателя | Конкретные, без риторики |

Beat sheet — не украшение. Это контракт с Писателем о том, что внутри секции.

### 1.4 Session

PM создаёт `Session_Glava_NN.md`:

| Блок | Содержание |
|------|-----------|
| T1: Метаданные | Глава, объём, калибровочные главы, ссылки |
| T2: Запреты этой главы | Конкретные, из тональной карты |
| T3: Разрешения / исключения | Что можно в этой главе нарочно |
| T4: Требования к аренам | Если нужны |
| T5: Лимиты сигнатурных фигур | «Не потому что X» ≤ N на главу |
| T6–T12: Доп. правила | По необходимости |

### 1.5 Handoff PM → Писатель

PM проверяет Contract 1 (`architecture/handoff_contracts.md`). Передаёт: MATERIAL + Session.

## Фаза 2: Написание (Писатель)

### 2.1 Подготовка

Писатель читает:
- `Session_Glava_NN.md` — правила сессии
- `MATERIAL_Glava_NN.md` — beat sheets
- Калибровочные главы — эталон тона
- `tonal_compass.md` — микрорежимы

**Не читает**: WebSearch, WebFetch — источники уже в MATERIAL.

### 2.2 Секция за секцией

Алгоритм на каждую секцию:

```
1. Прочитать beat sheet секции
2. Написать секцию, следуя beats
3. Пост-контроль:
   - Плотность: ≥ 4 утверждения на 100 слов
   - Объём: ±10% от target
   - Микрорежим: соответствует тональной карте
   - Запреты из T2: не нарушены
4. Только после прохождения — следующая секция
```

Секция — атомарная единица написания. Нельзя писать следующую до контроля текущей.

### 2.3 Финальный контроль главы

После всех секций:
- Сигнатурная фигура: посчитать, ≤ 8 (или лимит из T5)
- «Паттерн»: ≤ 2 на главу, заменить остальные
- Обращение к читателю: только «ты» / «du»
- Открытие главы: сцена / парадокс / провокация, не абстракция
- Закрытие главы: удар или мост, не резюме

### 2.4 Handoff Писатель → Редактор

Проверить Contract 2. Файл главы: `status: review`.

## Фаза 3: Редактура (Редактор)

### 3.1 Что Редактор делает

Редактор **создаёт отчёт**, не правит текст.

Инструменты: Read, Grep, Write. Edit — запрещён.

### 3.2 Процедура

1. Grep по маркерам failure modes (FM-01 — FM-08)
2. Читать главу целиком — проверять тон, ритм, голос
3. Оценивать каждую секцию по чеклисту
4. Писать editorial report

### 3.3 Editorial Report

Формат: `Editorial_Report_Glava_NN.md`

```
## Критические нарушения (блокируют handoff)
## Значимые проблемы (требуют правки)
## Замечания (на усмотрение Писателя)
## Что работает (зафиксировать, не терять при правке)
```

Правило: Редактор **показывает автору, ждёт подтверждения**. Молча не правит.

### 3.4 Цикл: Редактор → Писатель → Редактор

Если есть нарушения: Писатель получает отчёт, правит, возвращает.

Редактор **не правит чужие правки** — только проверяет, что Contract 2 теперь выполнен.

При `clean` статусе — Handoff по Contract 3.

---

## Фаза 4: Гуманизация (Гуманизатор)

### 4.1 Предусловие

Статус главы: `clean`. Без этого — возврат.

### 4.2 Процедура

Гуманизатор читает `.claude/skills/humanizer/SKILL.md` → маршрутизация по языку:

- RU → `skills/humanizer/ru/SKILL.md`
- DE → `skills/humanizer/de/SKILL.md` *(TODO — блокер MdP)*
- EN → `skills/humanizer/en/SKILL.md` *(TODO)*

Два режима:
- **Audit**: статистический отчёт, изменений нет
- **Rewrite**: трёхпроходная правка, контроль реинтродукции

### 4.3 Три прохода

| Проход | Цель |
|--------|------|
| Pass 1 | Лексические маркеры (уровень слова) |
| Pass 2 | Структурные маркеры (уровень предложения/абзаца) |
| Pass 3 | Реинтродукция — не вернулось ли убранное |

Тональная карта книги перекрывает дефолтные правила гуманизатора.

## Карта статусов

```
draft → review → editing → clean → humanized → final
  ↑PM+Writer  ↑Editor  ↑Editor  ↑Humanizer  ↑Author
```

Возврат возможен с любого этапа. Возврат — норма, не сбой.

---

## Параллельная работа

Разные главы книги могут быть на разных фазах одновременно.

Запрещено:
- Передавать главу с незаполненным Contract
- Редактору — менять текст напрямую
- Писателю — писать без Session + MATERIAL

## Экстренные процедуры

### Truncated chapter recovery

Если глава была сокращена инструментом (потеря контента):
1. Найти последний `SOS_backup` в папке книги
2. Сравнить с текущей версией (Grep по уникальным фразам)
3. Восстановить вручную — не переписывать

*Источник: ОНМ HANDOFF_2026-04-14.md — 13 глав с потерей при cleanup*

### Duplicate annotation removal

Если PM создал дублирующиеся аннотации источников:
1. Grep по первым 5 словам каждой аннотации
2. Оставить одну — ту, где есть конкретный фокус для главы
3. Удалить остальные без замены

*Источник: MdP — 19 дублированных аннотаций*
